# STRATUM — концепция платформы (v1.1)

## Позиционирование

**STRATUM** — Agentic Enterprise Transformation Platform для среднего и крупного бизнеса.
Платформа проектирует и управляет переходом к агентной модели, **не исполняя** функции отдельных агентов.

Ключевой принцип: **нет источника — нет вывода**. Где покрытия недостаточно, система задаёт точечные вопросы, а не домысливает.

## Методология: пять слоёв

| # | Слой | Практика | MVP |
|---|------|----------|-----|
| 1 | Стратегия и аппетит к автономии | TOGAF Strategy | да |
| 2 | Процессы и точки решений | Parasuraman et al., 2000 | да |
| 3 | Данные и знания | DAMA-DMBOK | да |
| 4 | Инструменты и интеграции | TOGAF App/Tech | V2 |
| 5 | Управление и надзор | NIST AI RMF, ISO/IEC 42001 | V3 |

Автономия агента растёт только вместе с доказанной управляемостью и регуляторным соответствием.

## Логика MVP

1. **Приём документов** → классификация по слоям, извлечение фактов с атрибуцией, версионность.
2. **Карта покрытия** → статус / слепые зоны / порог выводов.
3. **Автопрохождение** слоёв 1–3 → findings & proposals.
4. **Вопросы** → ответы = первоклассные источники.
5. **Утверждение** → в единую модель попадают только approved.
6. **TO-BE / roadmap / ROI** → прогноз с явными допущениями.
7. **Регуляторный фильтр РФ** → block/warn/pass на кейсах.

## Доработка концепции (относительно ТЗ v1.0)

1. **Порог покрытия как продуктовый контракт.** Пока `score < threshold` или слой не MVP — UI и API запрещают «уверенные» выводы (`can_infer=false`).
2. **Ответ = документ.** Ответы на вопросы попадают в facts с `document_id=answer:<id>` и могут порождать insight на утверждение.
3. **Agent Passport отложен в V3**, но модель уже содержит узлы типа `agent` в едином графе, чтобы не ломать связность AS-IS/TO-BE.
4. **Регуляторика как runtime-фильтр**, а не чеклист в конце: кейс с автономией 5 на деньгах блокируется до попадания в дорожную карту исполнения.
5. **Метрики Engine** (точность извлечения, галлюцинации, полнота) — first-class на обзоре; в MVP классификатор детерминированный (keyword + attribution), готов к замене на LLM с той же схемой атрибуции.
6. **Профиль заказчика** (внутренний инструмент / продукт; ПДн да/нет; КИИ/ГИС) влияет на жёсткость фильтра — в демо заложен «обычный бизнес» с warn по реестру ПО.

## Архитектура реализации

- **Backend:** Python / FastAPI, in-memory snapshot + seed «СеверПром».
- **Frontend:** React / Vite / Tailwind — landing + workspace модули.
- **Контракт:** `/api/snapshot` как единый агрегат состояния.

## Этапы

- **MVP** — слои 1–3, покрытие, вопросы, TO-BE, ROI, регуляторный скрининг.
- **V2** — слой 4, инициативы, детальная архитектура агентов.
- **V3** — Agent Passport, governance/надзор, фактический ROI.
- **V4** — непрерывная оптимизация агентной организации.
